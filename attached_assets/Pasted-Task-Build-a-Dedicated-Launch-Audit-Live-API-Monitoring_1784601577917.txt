Task — Build a Dedicated Launch Audit & Live API Monitoring Page

What & Why

Create a completely separate in-app page called:

Launch Audit

This page should act as the central control center for checking whether the entire application is ready for production.

It must not be placed inside another dashboard, hidden under an existing panel, or mixed into the Accuracy Dashboard.

The page should provide two things:

1. A full on-demand Launch Readiness Audit when I press one button.
2. Continuous live monitoring of all connected APIs, showing which providers are currently active, healthy, failing, unused, or serving as fallbacks.

Do not change prediction formulas, weights, calibration, recommendation logic, or model behavior as part of this task.

This task is operational monitoring, auditing, reporting, and production readiness only.

PAGE LOCATION

Add a dedicated page named:

Launch Audit

It should be accessible from the Developer/Admin area of the app.

Do not place it in the public user navigation.

Do not add it to the normal prediction workflow.

Restrict access to Owner/Admin accounts.

PAGE HEADER

Display:

Launch Audit

Subtitle:

Run a complete production-readiness check and monitor all active data providers.

At the top of the page include:

- Overall System Status
- Last Full Audit timestamp
- Current production engine version
- Current calibration version
- Current active configuration version
- Latest deployment timestamp
- Current environment: Development / Staging / Production
- Number of unresolved Critical findings
- Number of unresolved High findings

MAIN ACTION BUTTON

Add one primary button:

Run Full Launch Audit

When pressed, it should execute a complete read-only audit across the entire application.

The audit must not change production data, weights, calibration, thresholds, engine settings, subscriptions, or provider priorities.

Display progress while the audit runs.

Example progress stages:

1. Checking prediction engine
2. Checking database
3. Checking APIs and providers
4. Checking background jobs
5. Checking grading
6. Checking Walk-Forward
7. Checking Shadow Replay
8. Checking calibration
9. Checking subscriptions and payments
10. Checking security
11. Checking mobile UI and routes
12. Checking monitoring and rollback readiness
13. Generating final report

FULL AUDIT CATEGORIES

The audit should check all of the following.

1. Prediction Engine

Verify:

- Engine loads successfully
- Current engine version is recorded
- Current calibration version is recorded
- Current configuration version is recorded
- Identical inputs return identical outputs
- Recommendation logic does not produce invalid combinations
- Tie-break matches cannot receive a strong recommendation
- Missing-data rules are active
- Stale-data rules are active
- Force Signal predictions remain isolated
- Production prediction path is using the expected active configuration
- No inactive or deprecated module is unexpectedly being called

2. Database

Verify:

- Database connection is healthy
- All required tables exist
- All expected migrations completed
- No failed migrations
- No missing required indexes
- No obvious duplicate prediction rows
- No orphaned records
- No broken foreign-key relationships
- Candidate configurations are versioned
- Active production config is identifiable
- Specialist model rows exist where expected
- Player stats cache is populated
- Latest backup timestamp is available
- Storage growth is within acceptable limits

ACCEPTANCE TESTS

✓ Launch Audit exists as its own dedicated page.

✓ It is accessible only to Owner/Admin accounts.

✓ Run Full Launch Audit executes a read-only audit.

✓ The audit checks all required categories.

✓ Live API monitoring shows every configured provider.

✓ Providers are correctly labeled as primary, fallback, active, unused, disabled, healthy, degraded, or failing.

✓ The page shows which providers are currently being used by the app.

✓ Test Provider works without exposing credentials.

✓ Test All Providers uses lightweight health checks.

✓ Live health cards refresh without rerunning the full audit.

✓ Audit results are saved historically.

✓ Previous audits can be opened.

✓ Critical findings force Not Ready status.

✓ The audit never changes production model settings.

✓ The audit never deploys a candidate.

✓ The audit never changes calibration.

✓ The audit never makes a real payment.

✓ The page works cleanly on a phone.
